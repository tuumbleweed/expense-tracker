# Review findings

## Remaining Issues

- **Reports normally use analysis time as purchase time.** The producer schema (`src/pkg/llm/analyze-receipt.go:ReceiptAnalysis` and image-analysis schema) contains no receipt date. `src/cmd/report/main.go:determineReceiptTime` therefore uses run metadata. Processing an old receipt places it in the processing month. Extract and validate a purchase date and make fallback reporting explicit.
- **Money types disagree across producer and report.** Extraction permits floating-point amounts; reporting decodes them into `int64`. Fractional values allowed by the schema cause JSON decoding to fail and the entire receipt to be skipped. Use one shared money representation and validate COP integer amounts at ingestion.
- **Reconciliation is advisory model output.** The optional mismatch flag checks a model-generated string rather than recomputing sums; category keys are strings without schema enums or local validation. Reports can display a receipt total inconsistent with category sums, so percentages need not sum to 100%. Recompute totals, validate category membership, and explicitly report unreconciled differences.
- **Price-hint truncation appears incorrect.** `src/pkg/ocr/regex.go:ExtractPriceCandidates` says a trailing misread tax marker should be removed, but retains the last three digits: `90.1004` becomes `90.004`, not `90.100`. Correct the heuristic and add focused examples. The image remains primary evidence, but misleading hints can affect extraction.
- **Reprocessing can double-count purchases.** The pipeline creates a fresh run for each execution and the report includes every matching analysis file; there is no receipt identity/deduplication step. Add a stable input hash or explicit selection of accepted runs. Additionally, second-resolution run directory names can collide across concurrent runs or fast OCR-only calls (`src/pkg/ocr/pipeline.go`); use exclusive unique directory creation.
- **Standalone analysis assumes JPEG.** `src/cmd/analyze-receipt/main.go` hard-codes `orig.jpg`, while OCR can preserve `.jpeg` or `.png`. Reuse the combined pipeline's original-image discovery.
- **Batch failure is not reflected in exit status.** The combined command logs skipped files and returns normally even if every image fails. Return an appropriate nonzero status or machine-readable outcome for automation.
- **Response edge cases lack robust handling.** `src/pkg/openai/run.go` guards access to output-token details using the input-details pointer, permitting a nil dereference for some usage shapes. `responses.go:waitForResponseCompletion` accepts `incomplete` as success, leading to downstream JSON failures for truncated output. Guard the correct fields and handle incomplete results explicitly. These are static findings; no live failure was reproduced.
- **Validation coverage is absent.** No tracked tests or CI were found. Prioritize local fixtures for price hints, date selection, amount decoding, reconciliation, duplicate inputs and batch failures; live API tests are unnecessary for these checks.
- **Existing setup/deployment instructions are incomplete.** Root README points at a missing default config and calls the model configurable despite a logger-only config struct. Native headers are described as optional even though gosseract uses CGO. `build/Dockerfile` builds nonexistent `src/cmd/my-entrypoint/main.go`, omits OCR dependencies and starts a shell. Correct the CLI documentation and replace the placeholder container recipe only if container deployment is actually needed.

## Simplification Opportunities

- **Share the receipt contract.** Report-local structs duplicate extraction types with incompatible numeric fields. Text-only and image-based analysis also duplicate schema/prompt construction, including divergent reconciliation tolerances. Centralize the data model, schema, categories and deterministic validation; keep only input-specific prompt differences.
- **Reduce scaffold scope.** Generic mail-provider packages, Echo middleware and example commands are separate from the receipt workflow and enlarge dependency maintenance. If they serve no intended use, move them into a starter repository or remove them in a separately reviewed change. AWS, Echo and GORM declarations do not justify describing this project as a cloud service or database application.

These findings describe source behavior or clearly labeled static risks, not measured production incidents. Suggested changes have not been applied.
